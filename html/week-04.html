Feedback Loops and the Economics of Defects

Introduces the single idea that explains almost every SDLC practice: the cost of fixing a defect scales with how long it survives undetected. Students measure their own feedback loops with a stopwatch and discover where their time actually goes.

20 minutes instruction  •  25 minutes workshop

By the end of today you can…

  1. Explain the defect-cost curve and, importantly, its honest limitations as evidence.
  2. Measure the length of their own feedback loops (edit-to-signal) and identify the longest one.
  3. Reframe every practice in the rest of the course as either 'shorten a loop' or 'catch a defect earlier'.

Two ways this goes

The same phase of the lifecycle, done well and done badly — both from real projects

When the process holds

Google's presubmit checks

Google runs a large battery of automated checks before code can be merged, catching entire classes of defects at review time rather than in production. The investment is enormous; so is the codebase.

When it doesn’t

Knight Capital, 2012

A deployment reached only 7 of 8 servers, reactivating dormant code on the eighth. 97 automated emails flagged the error before markets opened; none were designed as alerts, so nobody read them. In 45 minutes the firm lost over $460 million. The signal existed. The loop was never closed.

AI in the loop

You will use AI this week. Here is where it earns its place — and where it lies to you.

Use it for

Treat AI as a sub-second reviewer that runs before your slower, more reliable checks - never instead of them.

Try this prompt

"Here is a diff. Without running it, list the three most likely ways this breaks in production, ordered by probability. For each, name the specific test I should write."

Do not trust

AI review feels like a fast loop but has a different error profile than a test: it catches plausible-looking mistakes and misses subtle-but-real ones. Never let a green AI review substitute for a red test.

Stopwatch Your Loops

The 25-minute block

  1. 0:00-0:10
    Students open a real project on their laptop and time, with an actual stopwatch: (a) edit to syntax error visible, (b) edit to test result, (c) edit to running app, (d) commit to CI verdict. Record real numbers.
  2. 0:10-0:16
    Plot the class distribution on the board. The spread is usually enormous - some students get CI feedback in 40 seconds, others have no CI at all.
  3. 0:16-0:22
    Pairs: pick your single longest loop and design the cheapest intervention that would halve it. Not the best intervention - the cheapest.
  4. 0:22-0:25
    Commit publicly: each student names the one loop they will shorten before Week 5.

Homework — Loop Measurement Report

Estimated time: 90 minutes

  1. Produce a table of your four measured loop times, with the tooling that produces each signal.
  2. Implement the cheap intervention you committed to. Measure again. Report the before/after honestly, including if it didn't work.
  3. Read the Knight Capital SEC order paragraphs 12-30. In 250 words, identify the three specific loops that were open, and which single one you'd close first if you had one engineer-week.
  4. AI task: have an assistant review a diff you actually wrote this week. Log what it caught, what it missed, and what it hallucinated.
